「模型管理」页的「我的模型」标签汇总本机所有可用模型，每个模型都可以单独配置推理参数。启动 API 服务时，应用按这些参数为每个模型生成 llama-server 预设。

## 模型列表

列表合并了两个来源，并用标签区分：

- **下载路径**：通过「下载模型」标签下载的模型；
- **外部路径**：通过「选择文件夹」导入的已有目录。

每个模型卡片显示名称、架构（如 `qwen2`）、量化等级（如 `Q4_K_M`）、体积和完整路径。支持多模态的模型带「多模态」标记（检测到同目录的 mmproj 文件）。模型文件有变动时点「刷新」重新扫描。

## 本地量化（仅桌面）

在「我的模型」里**右键点击一个模型卡片**，选择「量化…」，即可用 llama.cpp 自带的 llama-quantize 工具把模型转换为更小的量化版本：目标量化支持 q4_k_m / q5_k_m / q8_0 / f16 四档（q4_k_m 体积/质量最均衡，f16 无损），输出文件自动按 `原名-量化等级.gguf` 命名（可修改），保存在源文件同一目录。运行中展示实时日志并可取消；完成后新文件出现在源模型旁边，「我的模型」会自动刷新显示。

此功能仅桌面端提供（量化工具随 llama.cpp 完整发行包安装，与 llama-server 同目录；安卓包不含该工具）。注意：对已经量化过的模型再次量化需要源为高精度版本，否则 llama-quantize 会在日志中报错。

## 打开模型设置

点击模型卡片右侧的齿轮按钮，进入该模型的独立设置页。参数按「基础 / LoRA 适配器 / 推理 / 内存加载 / 多 GPU / 长上下文 / 高级」七个标签组织，每项都带使用建议。

其中「LoRA 适配器」标签管理**该模型专属**的 LoRA 挂载：把 Unsloth 等工具训练并导出的 LoRA 适配器 GGUF 放入「模型下载目录/lora」文件夹，点「刷新扫描」，每个文件会列出体积与 Alpha，并按 GGUF 元数据自动识别是否为有效适配器。打开开关、把权重（scale，0–4，默认 1.0）调到想要的大小后点「保存适配器」，适配器会在服务启动时以 `--lora-scaled` 挂载到这个模型上（每个模型挂自己的适配器，互不影响；适配器要与基座模型架构匹配才能加载）。服务运行中可点「应用到运行中服务」尝试热更：安卓直连模式即时生效；桌面端受当前 llama.cpp 的 router 限制会提示「将在下次启动服务时生效」，重启服务即可。

## 一键调优

设置页右上有「一键调优」按钮，不需要你理解任何参数：

1. 点一下，应用读取模型 GGUF 文件的真实指标（层数、注意力头结构、KV 缓存几何、训练上下文、MoE 专家规模），结合本机硬件快照（显卡显存、内存、CPU 核心数、实测内存带宽）计算一组最优参数；
2. 计算结果**实时填进表单**——每一项（GPU 层数、上下文大小、缓存类型、CPU 线程等）都直接更新，你可以在保存前逐项检查、手动微调；
3. 确认无误后点「保存设置」。

调优会按你在设置页选择的**推理显卡**规划显存：多卡机器上选了哪张卡，就按哪张卡的显存算。可选方案包括全部卸载到 GPU（最快）、MoE 模型的 cpu-moe（专家层留内存、其余上 GPU）、部分卸载（显存放不下的兜底）和纯 CPU（无显卡时），上下文长度也会在显存预算内尽量选大。Apple Silicon（macOS arm64）走 Metal 方案：统一内存让全部层驻留 GPU，上下文按内存预算选最大（Flash Attention 暂不自动开启）；Linux 上 AMD / Intel 显卡同样会选中 Vulkan 构建进行 GPU 加速。

## 常用参数速查

| 参数 | 含义与建议 |
| --- | --- |
| GPU 层数 | `auto` 全部放进显存（推荐）；显存偏小时填数字做部分卸载；纯 CPU 推理选 `0` |
| 上下文大小 | 模型一次能"看到"的文本量；对话越长设越大，受显存限制 |
| CPU 线程 | `-1` 自动；CPU 较弱或发热明显时调低 |
| Flash Attention | 推理加速且省显存，有 GPU 时推荐开启 |
| cpu-moe | MoE 模型（DeepSeek、Qwen3-MoE 等）显存不足时，把专家层留在内存 |
| KV 缓存类型 | `q8_0` 几乎无损且省显存，推荐；默认 f16 |
| 加载方式 | 默认 mmap 加载最快；内存充裕可选 mlock 防换页 |
| 切分方式 | 单卡选 `none`；多卡默认 `layer` 稳定 |
| 投机解码 | 「高级」标签。`ngram-simple` / `ngram-mod` 为 n-gram 自投机：无需草稿模型、零额外显存，对重复/结构化输出（代码、模板文本）有加速，其他场景可能变慢；`draft-mtp` 为 MTP 投机预测，需模型支持；留空关闭 |

> 注：Android 为纯 CPU 构建，页面不显示 GPU 层数、Flash Attention、cpu-moe 等 GPU 专属参数；「加载方式」中的 `dio` 仅 Windows / Linux 提供。Android 会自动识别 SoC 型号（如骁龙 / 天玑，来自系统属性）；「一键调优」在安卓上线程数上限为性能核数量（big.LITTLE 小核不参与推理线程），且纯 CPU 方案的调优结果提示不再显示 GPU 层字段。

## 服务运行中修改参数

参数预设是在**服务启动时**生成的。如果服务正在运行，保存后页面顶部会提示「参数将在下次启动服务时生效」——到「API 路由」页重启服务即可应用新参数。
